This module links business requirements to project tasks, so each
requirement can track the tasks that implement it and the hours
allocated to them.

It fills the gap left by the ``business_requirement_*_project`` modules
that were not migrated beyond earlier versions: instead of generating
projects and tasks from requirement resource lines, it provides a
simple, direct link between a business requirement and the project tasks
that execute it, with task counters and an allocated hours rollup on the
requirement.

Usage
=====

1. Open a business requirement and set its **Project**.
2. Use the **Create Task** button in the header to create a task already
   linked to the requirement: the task form opens with the requirement,
   project, customer and name pre-filled.
3. Alternatively, open any project task and set its **Business
   Requirement** field. If the task has no project yet, it inherits the
   project of the requirement; if both projects differ, a non-blocking
   warning is shown.
4. The **Tasks** smart button on the requirement shows the number of
   linked tasks and opens their list. The requirement also exposes the
   number of open tasks and the total allocated hours of its tasks.
5. In the tasks search view you can filter tasks that have a business
   requirement and group tasks by requirement.

A requirement with linked tasks cannot be deleted.

Known issues / Roadmap
======================

- Roll up the real hours spent (``effective_hours``) on the linked
  tasks. That field is defined by ``hr_timesheet``, so it belongs in a
  separate glue module (e.g. ``business_requirement_task_timesheet``) to
  keep this module free of the timesheet dependency.
